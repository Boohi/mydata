# Planning inside the Superify contract

The existing goal and progress contracts remain normative. This reference adds
planning technique; it changes no schema, initialization order, approval,
activation, receipt, association, or resume requirement.

Build on accessible conversation decisions, current project docs, existing
issues, and actual runtime evidence. Preserve proposition categories: a sketch
is not a requirement, and an open possibility is not current scope. Reuse domain
terms; use `docs-ops` only when settled language or a consequential decision needs
an existing documentation home.

Make the first slice independently demonstrable, with its user value, required
proof, exclusions, and real blocking dependencies. Keep the authoritative plan
in the existing artifact. Issue links and investigation notes are evidence or
projections of that plan, not a second task map, goal, or executor.

Research discoverable facts with bounded sidecars. Ask only consequential
questions under the goal contract's one-question-per-turn limit; use zero when
reversible assumptions suffice. Stop at that sufficiency boundary rather than
trying to exhaust every branch of a design tree.

When a real human decision remains, prepare the concrete package, comparison,
prototype result, or evidence first. Keep the review concise with links to detail.
This moves preparation before the human checkpoint while preserving the exact
later-turn activation permission and causal receipt sequence.

On same-state resume, read and reconcile the documented association. Planning
improvements never justify another initialization, resetting active state, or
creating a second goal. Compilation remains separate from target implementation.
